## Project Canon Snapshot
- Strict GRACE is artifact-first: requirements, technology, development plan, knowledge graph, and verification matrix must exist before code changes. Source: [`/opt/astro-project/GRACE.md`](file:///opt/astro-project/GRACE.md) sections `5`, `7`, `8`, `9`, `10`, and `13`.
- Controller/worker/reviewer separation is mandatory. Controllers own shared architectural truth; workers stay inside explicit write scope; reviewers judge packet compliance and evidence quality. Source: [`/opt/astro-project/GRACE.md`](file:///opt/astro-project/GRACE.md#10).
- Addressability is a hard requirement:
  - module contracts: `START_MODULE_CONTRACT` / `END_MODULE_CONTRACT`
  - module maps
  - function contracts for critical entrypoints
  - paired semantic blocks: `START_BLOCK` / `END_BLOCK`
  Source: [`/opt/astro-project/GRACE.md`](file:///opt/astro-project/GRACE.md#7).
- Structured logs are verification evidence, not decoration. Critical paths should emit module/function/block/event/result/trace identifiers. Source: [`/opt/astro-project/GRACE.md`](file:///opt/astro-project/GRACE.md#8).
- Verification is gate-based and evidence-driven: deterministic asserts first, then trace assertions, then module/wave/phase gates. Green tests alone are not enough without post-test evidence review. Source: [`/opt/astro-project/GRACE.md`](file:///opt/astro-project/GRACE.md#9).
- Local project interpretation stays explicit in [`/opt/astro-project/docs/GRACE_HOME.md`](file:///opt/astro-project/docs/GRACE_HOME.md): bounded work, packet-first execution, and minimal-sufficient regression over blind full reruns.
- Repo baseline is not clean. [`/opt/astro-project/technology.xml`](file:///opt/astro-project/technology.xml) records git snapshot `0cba3cf07ea563306bdd6e887d7b9256c3edc190`, tag `prod-release-20260327`, `worktree_state="dirty"`, and `strict_grace_status="in_progress"`.
- Stable business invariants this refactor must not disturb:
  - Telegram identity is the canonical user key
  - engine-first chart/facts policy
  - typed JSON boundaries
  - async report lifecycle persistence
  - best-effort notification delivery
  - explicit defect tracking instead of silent scope cuts
- This feature adds a local size adaptation, not a replacement for strict GRACE: touched backend Python files should be `<=1000` physical lines and oversized functions should be split conservatively under the `4000`-token target. Source: feature brief plus [`/opt/astro-project/GRACE.md`](file:///opt/astro-project/GRACE.md#7.6).
