## Known Boundaries
- Scope is narrow: fix misleading `FAIL_NO_EVIDENCE`, classify real Today degradation as `unexpected-degradation` instead of no evidence, separate Week fallback/degradation from missing evidence, and refresh Admin/Catalog evidence freshness. No redesign of product behavior, auth, pricing, report schemas, or frontend UI.
- Do not weaken observability gates or hide real degradation by marking it clean. Explicit degraded states are only acceptable when reason codes make the expectation clear and approved.
- Preserve GRACE rails on touched modules: keep module contracts, module maps, function contracts, and paired `START_*` / `END_*` blocks intact.
- Admin surfaces are higher risk because the snapshot still documents server-side admin auth gaps. Treat `DEFECT-ADMIN-SERVER-AUTH` as a safety rail.
- Fallback is not a blank check. Missing evidence is distinct from degraded evidence.
- `verification-matrix.md` is legacy continuity and points to `docs/REGRESSION_MAP.md`, which was not supplied here; treat the mapping as partial unless refreshed.
- The snapshot boundary remains commit `0cba3cf07ea563306bdd6e887d7b9256c3edc190` with a dirty worktree. Source: [technology.xml](/opt/astro-project/technology.xml#L2).
- Recent manifests in context show overlapping backend and Week-related workstreams; avoid assuming this feature owns producer redesign unless evidence proves the reviewer/tooling layer is insufficient.

## Verification And Evidence Map
- Mandatory post-test review: after any `backend:quick`, `frontend:quick`, `smoke`, or targeted Today/Week/Read/Admin/Catalog scenario, run `python3 tools/post_test_review.py --profile today-week --since 30m --report-format md` and inspect the digest, not just exit code. Source: [docs/POST_TEST_OBSERVABILITY_REVIEW_2026-04-01.md](/opt/astro-project/docs/POST_TEST_OBSERVABILITY_REVIEW_2026-04-01.md#L25).
- Required inputs for `today-week`: `logs/feed.jsonl`, `logs/report.jsonl`, `logs/admin.jsonl` when relevant, latest `trace_id` / `report_id` / `correlation_id`, plus replay summaries and fallback counters. Source: [docs/POST_TEST_OBSERVABILITY_REVIEW_2026-04-01.md](/opt/astro-project/docs/POST_TEST_OBSERVABILITY_REVIEW_2026-04-01.md#L51).
- Verdict vocabulary: `clean`, `degraded-but-expected`, `unexpected-degradation`, `no-evidence-blocker`; final gate outputs are `PASS_CLEAN`, `PASS_WITH_EXPECTED_DEGRADATION`, `FAIL_OBSERVABILITY_GATE`, or `FAIL_NO_EVIDENCE`. Source: [docs/POST_TEST_OBSERVABILITY_REVIEW_2026-04-01.md](/opt/astro-project/docs/POST_TEST_OBSERVABILITY_REVIEW_2026-04-01.md#L27).
- Evidence flows to expect in digests: `FLOW-DAILY-FEED`, `FLOW-DAY-BRIEF`, `FLOW-WEEK-BRIEF`, `FLOW-REPORT-WORKFLOW`, `FLOW-ADMIN-OPS`, `FLOW-FORECAST-CATALOG`.
- Required structured fields for evidence digestion: `flow_id`, `surface`, `event`, `result`, `fallback_mode`, `reason`, `primary_reason_code`, `reason_codes[]`, `factor_count`, `explanation_depth`, and correlation fields.
- Evidence substrate comes from the existing watchers/replayers: `tools/log_watch/feed_admin_watch.py`, `tools/admin_logs/replay_last.py`, `tools/feed_logs/replay_last.py`, `tools/log_watch/forecast_catalog_watch.py`, and `tools/log_watch/billing_watch.py`.

## Architect Handoff Notes
- Keep the slice boundary on observability repair, not product redesign. If a fix changes behavior, classify that behavior change explicitly before code touches.
- Separate producer fixes from reviewer/tooling classification fixes when slicing. Only combine them if the packet scope is tiny and the dependency is proven.
- If logs already contain concrete degraded evidence with trace or request identifiers, the correct output is `unexpected-degradation` or `degraded-but-expected`, not `FAIL_NO_EVIDENCE`.
- Treat Admin and Catalog freshness as a provenance problem first: either the producer command is missing or the review window is wrong.
- Use the existing watcher/replay helpers as the evidence source of truth before introducing any new abstraction.
- If a wave crosses the snapshot boundary, refresh the snapshot before coding so the gate stays reproducible.
