# GRACE Slice: рубрикатор качества "глубже большинства астрологов"

## Intent / Назначение
Этот документ задает рабочий порог качества для `natal_master`, `week_forecast`, `month_forecast`, `year_forecast` и сжатого daily-слоя. Он нужен не для самовнушения, а для холодной проверки: продукт реально дает более глубокий, персонализированный и практически полезный разбор, чем типовой астрологический отчет, или только кажется таким.

Главный принцип: оцениваем не "красоту текста сама по себе", а связку `facts-first -> insight_pack -> user-visible blocks -> mobile read`.

## Scope / Границы

### In Scope
- Натал: `build_section_context()` + `section_context.insight_pack` + `cross_links`.
- Forecast: shared forecast context и read surfaces `/week`, `/read/[id]`.
- Daily: короткий слой полезности, если он опирается на реальные facts и не ломает mobile scan.
- Voice и narrative bar из `STYLE_CONTRACT.md`.
- User-visible JSON blocks из `frontend/components/blocks/report-renderer.tsx`.

### Out Of Scope
- Хорар как отдельный домен: у него другой порог, там важнее вердикт, тайминг и риск.
- "Истинность астрологии" как дисциплины. Здесь измеряется качество продукта как аналитического и редакторского инструмента.

## Anchors / Архитектурные опоры
- `backend/app/services/report_workflow.py`: канонический смысловой слой для натала это `section_context.insight_pack`, а не свободная импровизация модели.
- `backend/app/llm/orchestrator.py`: premium natal sections уже получают runtime hint из `STYLE_CONTRACT.md`; секция должна verbalize deterministic conclusions, а не заменять их.
- `STYLE_CONTRACT.md`: life-first, формула `сцена -> механизм -> зрелый ход`, запрет на sign-by-sign и aspect-by-aspect шаблон.
- `docs/REPORT_STRUCTURES.md`: качество оценивается внутри реальных section contracts, а не в вакууме.
- `docs/BLOCKS_SCHEMA.md` и `frontend/components/blocks/report-renderer.tsx`: scoring идет по тому, что реально можно читать в `paragraph/list/callout/key_value/rating/traffic_lights`, с учетом mobile.
- `tests/test_natal_section_context.py` и `tests/repro_hallucination.py`: hard evidence для `insight_pack`, `cross_links` и анти-галлюцинационного floor.

## Hard Gates / Автопровал
Если любой пункт ниже красный, формулировка "глубже большинства астрологов" запрещена независимо от редакторского балла.

1. Есть hard hallucination или противоречие `facts_v1` / `insight_pack`.
2. Natal-секция, которая должна быть facts-first, не использует `insight_pack`/`cross_links` и уходит в новую "теорию личности".
3. Вывод ломает block contract, unreadable на `/read/[id]` или `/week`, либо превращается в fallback-only режим.
4. `cheap` режим теряет каркас отчета, уходит в общий шаблон или ломает JSON blocks.
5. Mobile-first провален: первый экран секции не дает главной мысли, либо секция превращена в тяжелую стену текста / таблиц.

## Scoring / Шкала 0-5
Оценка идет по пользовательскому выводу. Для каждого кейса ставится 10 оценок по шкале `0..5`. Общий балл: `0..50`.

| Критерий | `5` | `3` | `0-1` |
| --- | --- | --- | --- |
| Глубина | Несколько факторов собраны в один жизненный механизм; названы сила, цена перегиба и зрелый ход. | Есть один настоящий вывод, но часть текста остается перечислением. | Знак/дом/аспект идут списком без сборки. |
| Персонализация | Текст трудно переставить на другую карту без очевидной лажи; есть конкретные триггеры, условия, стиль реакции. | Есть персональные детали, но заметен слой общей психологии. | Генерик-портрет, который подходит "почти всем". |
| Cross-linking | Любовь, деньги, ядро личности, циклы или дни/недели связаны в один паттерн; `cross_links` реально отыграны. | Есть 1-2 локальных моста между блоками. | Секции живут островами. |
| Практическая польза | Советы следуют из механики; есть условия, темп, что делать/чего не форсировать. | Есть полезные советы, но часть звучит общо. | Коучинговые банальности без прикладной ценности. |
| Narrative quality | Выполнено `сцена -> механизм -> зрелый ход`; сильное начало, ясный ритм, хороший финал. | Понятно, но плосковато или ритм однотипный. | Учебник, эзотерический туман или разваленный текст. |
| Не-шаблонность | Нет повторяющихся заходов, клише и "У тебя X в Y, значит..."; секции отличаются по ритму. | Пара заметных повторов, но без полного ощущения шаблона. | Отчет звучит как конвейерный генератор. |
| Фактическая опора | Все ключевые выводы можно привязать к `facts_v1`/`insight_pack`; нет лишних выдуманных сущностей. | Противоречий нет, но часть фраз слишком расплывчата, чтобы доказать их опору. | Есть фактологический overreach или явная галлюцинация. |
| Cheap-model robustness | `cheap` держит тот же каркас и те же core claims; потеря качества минимальна. | `cheap` слабее, но не рушит структуру и не уходит в generic mush. | `cheap` ломает контракт или теряет смысловую сборку. |
| Mobile readability | Первый абзац самодостаточен; абзацы короткие; списки сканируются; тяжелые таблицы не доминируют. | Читать можно, но есть перегруженные куски. | На телефоне это стена текста или шумная мешанина блоков. |
| Fit по горизонту | Natal звучит как цельный портрет, week/month/year как навигатор, daily как короткий tactical layer. | В целом fit есть, но местами week звучит как mini-natal или natal как справочник. | Горизонт продукта не чувствуется. |

## Levels / Уровни
- `0-29/50`: шаблонно или поверхностно. Не дотягивает до ship-уровня.
- `30-37/50`: полезно, но это максимум "нормальный автоматический отчет".
- `38-42/50`: сильный продукт, сопоставим с добротным астрологом/редактором.
- `43-46/50`: выше большинства типовых астрологических отчетов.
- `47-50/50`: исключительный уровень.

## Claim Rules / Когда можно говорить "глубже большинства астрологов"
Нужны одновременно все условия:

1. Hard gates зеленые.
2. Median natal score по benchmark pack: не ниже `44/50`.
3. Median forecast score по benchmark pack: не ниже `42/50`.
4. По критериям `Глубина`, `Персонализация`, `Cross-linking`, `Фактическая опора` медиана не ниже `4/5`.
5. `cheap` вариант не падает ниже `38/50` и не теряет больше `4` баллов от основного режима на том же кейсе.

Без выполнения всех пяти условий формулировка "глубже большинства астрологов" запрещена; допустима только более слабая формула вроде "сильный автоматический разбор".

## Benchmark Protocol / Сравнение с типовым астрологическим отчетом
Чтобы не обманывать себя, сравнение должно быть blind и парным.

1. Собрать минимум `8` кейсов:
   - `4` timed natal case с разными dominant signatures/patterns;
   - `2` natal case с ограничением по времени рождения;
   - `2` forecast case (`week`/`month`/`year`) с разной плотностью событий.
2. Для каждого кейса подготовить минимум `3` текста:
   - наш продукт в основном режиме;
   - наш продукт в `cheap`;
   - внешний или архивный human/market report типового астрологического стиля.
3. Убрать брендинг, имена моделей и любые подсказки об источнике.
4. Два рейтера независимо ставят баллы `0..5` по всем 10 критериям.
5. Считать медиану по каждому критерию и по итоговому баллу.

Правило победы над "типовым астрологом":
- основной режим продукта должен обгонять внешний benchmark минимум на `4` балла из `50` по медиане на natal;
- минимум на `3` балла из `50` по медиане на forecast;
- выигрывать минимум `7/10` критериев;
- не проигрывать по `Фактической опоре` и `Mobile readability`.

Если внешнего blind benchmark нет, claim "глубже большинства астрологов" не используется вообще.

## Practical Notes / Практика применения
- Оценивается итог на read surface, а не prompt и не сырой JSON отдельно.
- Для natal высокий балл невозможен без реальной эксплуатации `insight_pack` и `cross_links`.
- Для forecast высокий балл невозможен, если неделя/месяц не дают ясный темп, точки решения и карту риска.
- Для daily не нужен "глубокий эссе-режим"; ему достаточно держать `Практическую пользу`, `Фактическую опору`, `Cheap-model robustness`, `Mobile readability`, `Fit по горизонту` на уровне не ниже `4/5`.
